# 주요 기능

## 1. 공공데이터 기반 재배 환경 추천

### 설명

사용자가 재배하고자 하는 버섯의 종류를 입력하면 공공데이터 기반 참조
테이블(`mushroom_reference`, Cultivation Service 소유)에서 해당 종의 최적 환경 범위를
조회해 추천합니다. 버섯 종류가 5가지로 고정되어 있어 항상 동일한 값이 나오므로,
Vector Search나 LLM 없이 직접 조회합니다.

### 제공 항목

- 온도 (범위)
- 습도 (범위)
- CO₂ 농도 (범위)
- 조도 (범위)

### 동작 과정

1. 사용자가 재배할 버섯을 선택합니다.
2. Cultivation Service가 같은 DB의 `mushroom_reference`를 내부 조회합니다.
3. 조회된 최적 범위를 추천값으로 반환합니다.
4. 사용자는 추천 범위를 참고해 자동 제어 기준값(위험 한계값)을 직접 입력합니다.
5. 저장 시 Cultivation Service가 단일 목표값을 허용 오차만큼 확장한 범위로 변환해
   저장합니다.

### 설명

### 모니터링 항목

## 4. 자동 환경 제어

### 설명

Rule Engine이 센서 데이터를 분석해 재배 환경을 자동으로 제어합니다.

### 자동 제어 대상

- 가습기, 환풍기, 냉각기, 히터, LED 조명

### 예시

- 습도가 기준 이하일 경우 가습기 자동 실행
- CO₂ 농도가 높을 경우 환풍기 자동 실행
- 온도가 높을 경우 냉각기 자동 실행

제어를 멈추는 기준은 범위 경계가 아닌 범위의 중앙값입니다(채터링 방지).

## 5. AI 생육 분석 (Vision)

### 설명

사용자가 직접 촬영해 업로드한 생육 사진을 AI Vision 모델로 분석해 현재 재배 상태를
판단합니다. 카메라 센서가 자동으로 촬영하는 방식이 아니라, 사용자가 앱/웹에서
사진을 찍어 업로드하는 방식입니다.

Vision 모델은 사전에 학습된 성장 단계별 이미지 패턴과 업로드된 사진을 비교해
지표를 산출하며, LLM은 그 지표를 해석하는 설명과 개선 방안만 생성합니다.

### 제공 정보

- 생육 점수, 균사 성장률, 갓 크기, 색상 상태, 병충해 여부, 성장 단계, 예상 수확
  시기, 환경 개선 제안

### 동작 과정

1. 사용자가 재배 중인 버섯 사진을 촬영해 업로드합니다.
2. Cultivation Service가 사진을 Photo Storage(MinIO 또는 로컬)에 저장합니다.
3. AI Service의 Vision 모델이 사진을 분석합니다.
4. LLM이 분석 결과를 해석해 자연어 설명과 개선 방안을 생성합니다.
5. 사용자는 즉시 결과를 확인하며, 분석 결과는 이후 추이 비교를 위해 영구
   보관됩니다.

## 6. 일일 피드백

### 설명

매일 두 가지를 함께 제공합니다. 첫째, 지난 24시간의 환경 통계(평균/최고/최저
온도·습도·CO₂·조도)를 요약합니다. 둘째, 사용자가 재배 환경(온도 등)을 수정했을 때
그 수정이 생육에 실제로 도움이 됐는지 비교해 알려줍니다. Daily Scheduler가 매일
23시에 실행되어 생성하며, 재배 기간이 한 달을 넘지 않는 도메인 특성상 별도의
주간/월간 리포트는 두지 않고 이 기능 하나로 통합해 제공합니다. 전날 생육 사진이
없으면 생육 비교 없이 안내 문구를 제공하며, 이 경우에도 환경 통계는 그대로
제공됩니다.

### 제공 내용

- 환경 통계 (평균/최고/최저 온도·습도·CO₂·조도)
- 환경 변경과 생육 추이의 상관관계 해석
- 사진이 없는 날의 안내 문구

## 7. 인사이트

### 설명

같은 버섯 종류이면서 유사한(오차 범위 내) 환경(온도/습도/CO₂/조도)으로 재배했던 다른
사용자들의 수확 사례를 둘러볼 수 있는 기능입니다. 일일 피드백이 자기 자신의 이력을
비교하는 것과 달리, 인사이트는 타인의 사례를 보여줍니다. 웹 챗봇의 `/인사이트`
명령어로 시작하며, 후보 리스트 조회 → 상세 조회 2단계로 이루어집니다.

재배 기간이 사용자마다 크게 달라 일자별로 정교하게 비교하거나 짧은 시간(예: 24시간)
단위로 평균을 비교하는 방식은 유의미한 차이를 만들기 어렵다고 판단해 채택하지
않았습니다. 대신 재배 전체 기간의 평균으로 유사 사례를 찾고, 그 사례가 실제로 겪은
기록을 그대로 보여주는 방식을 택했습니다.

수확(재배당 한 번)이 기록되면 AI Service가 그 사례를 `insight` 테이블에 즉시
저장해 둡니다.

### 제공 내용

- 후보 리스트: 같은 버섯 종류 + 유사 환경의 사례 중 내 재배를 제외한 최신순 최대 5개
- 후보 상세: 선택한 사례의 재배 기간 날짜별 환경 통계 + 일일 피드백, 수확일에는 수확
  시점 요약

### 동작 과정

1. (적재) 수확이 기록되면 AI Service가 환경 평균/생육 점수/수확량과 함께 한 줄 요약을
   `insight` 테이블에 저장합니다. 별도 배치나 임계치 없이 수확 시점마다 반영됩니다.
2. (후보 조회) `/인사이트` 입력 시 AI Service가 `insight` 테이블에서 같은 버섯 종류
   (정확히 일치) + 온습도/CO₂/조도(오차 범위)가 맞는 사례 중 내가 속한 재배를 제외하고
   최신순 최대 5개를 리스트로 보여줍니다. 이 단계는 LLM을 호출하지 않습니다.
3. (상세 조회) 후보 하나를 선택하면 그 재배의 `daily_feedback`을 날짜순으로 그대로
   보여주고, 수확일만 적재 시점에 만들어 둔 요약으로 대체합니다. 추가 LLM 호출은
   없습니다.

## 8. AI 챗봇

### 설명

재배 과정에서 발생하는 궁금한 사항을 자연어로 질문하고 AI에게 답변을 받을 수
있습니다. 용도가 다른 두 채널을 제공합니다.

- **웹 챗봇**: WebSocket으로 연결하는 채팅방입니다. 자연어 질문뿐 아니라 `/`로 시작하는
  명령어도 처리합니다 — 조리법 등 공공데이터 API 기반 정보 조회, `/인사이트` 명령어로
  유사 사례 후보 리스트 조회 후 선택 시 상세 조회(자세한 내용은 [인사이트](#7-인사이트)
  절 참고).
- **Telegram/Discord 챗봇**: 알림 수신 채널이면서 동시에 자연어 질의응답을 제공합니다.
  `/` 명령어나 여러 사용자가 함께 쓰는 채팅방 기능은 아직 제공하지 않습니다(설계 논의
  중).

### 예시 질문

- 왜 성장이 느린가요?
- 언제 수확하면 좋을까요?
- 현재 환경은 적절한가요?
- 어떻게 하면 생산량을 높일 수 있을까요?

### 예시 명령어 (웹 챗봇)

- `/조리법 표고버섯` — 공공데이터 API로 조리법 정보 조회
- `/인사이트` — 기존 인사이트 기능 호출

## 9. 버섯 가이드

### 설명

재배 생성 직후 버섯의 효능과 재배 시 주의사항을 자연어로 보여줍니다.
`mushroom_reference`의 텍스트 컬럼을 RAG 컨텍스트로 사용해 LLM이 자연스러운
문장으로 재구성합니다. 버섯 종류가 5종 고정이라 결과를 캐싱합니다.

## 10. 재배 이력 관리

### 설명

재배가 종료되면 결과를 저장하고 이전 재배와 비교할 수 있습니다. 재배 하나는
수확을 한 번만 기록합니다. 수확이 기록되면 AI Service가 생육 점수 평균과 환경 유지
점수를 합산해 상품 등급(TOP/HIGH/MID/LOW)을 비동기로 매깁니다.

### 관리 정보

- 버섯 종류, 재배 기간, 수확량, 수확 메모, AI 분석 결과, 상품 등급

### 활용

- 이전 재배 결과 비교, 생산량 변화 분석, 환경 개선 효과 분석

## 11. 실시간 알림

### 설명

환경 이상 또는 장치 이상이 발생하면 사용자에게 즉시 알림을 제공합니다.

### 알림 채널

- Telegram, Discord

알림 채널은 재배 단위로 등록하며, 등록하지 않은 재배는 해당 채널로 알림을 받지
않습니다.

### 알림 예시

- 습도가 권장 범위를 벗어났습니다.
- 환풍기가 자동으로 실행되었습니다.
- 센서 연결이 끊어졌습니다.
- 수확이 기록되었습니다 / 오늘의 일일 피드백이 도착했습니다.

## 12. 환경 데이터 시각화

### 설명

센서 데이터를 차트 형태로 시각화해 재배 환경의 변화를 쉽게 확인할 수 있습니다.

### 제공 차트

- 시간별 온도/습도/CO₂ 농도/조도
- 자동 제어 이력
- 환경 유지율

## 13. 회원 탈퇴

### 설명

사용자는 언제든지 회원 탈퇴를 요청할 수 있습니다.

### 처리 내용

- `users.status`를 `'DELETED'`로 변경하고 `deleted_at`을 기록하는 Soft Delete
- Refresh Token 즉시 삭제 (동기 처리)
- 보유 재배 데이터 비활성화 (이벤트 기반, Cultivation Service)

### 특징

탈퇴 즉시 개인정보를 완전히 삭제하지 않고 Soft Delete로 처리합니다. 사용자 행
자체는 삭제하지 않으며, 후속 처리(재배 비활성화)는 `UserDeletedEvent` 기반으로
비동기 처리됩니다.

## 14. 문의(Inquiry)

### 설명

시스템 관리자를 제외한 모든 역할이 문의를 남길 수 있고, 시스템 관리자가 답변하거나
처리합니다. 문의 유형은 일반 문의와 경작 문의 두 가지입니다.

### 유형별 처리

- 일반 문의(GENERAL): 관리자가 텍스트 답변을 남기면 상태가 `OPEN → ANSWERED`로
  바뀝니다.
- 경작 문의(CULTIVATION): `cultivationId`로 특정 재배를 지정합니다. 관리자는 텍스트
  답변 대신, 문제가 된 재배 자체를 조회 후 삭제할 수 있습니다(예: 재배 중 오류가
  발생해 삭제하고 다시 생성해야 하는 경우). 삭제가 이루어지면 상태가
  `OPEN → CLOSED`로 바뀝니다.

### 특징

Cultivation Service의 `inquiry` 테이블에 저장됩니다. 경작 문의의 `cultivation_id`는
같은 DB에 있음에도 의도적으로 FK를 걸지 않은 소프트 참조입니다 — 재배가 삭제된
이후에도 "어떤 재배에 대한 문의였는지" 이력을 남기기 위해서입니다. 관리자 여부는
Auth DB의 `users.role`(USER/ADMIN)을 JWT 클레임으로 확인합니다.
